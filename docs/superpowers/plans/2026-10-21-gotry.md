# gotry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `github.com/MrVSiK/gotry`, a dependency-free `http.RoundTripper` that adds retries (classified triggers, backoff, Retry-After, idempotency gating, budget, circuit breaker) and request hedging.

**Architecture:** One package `gotry` at the module root. Pure building blocks (backoff, classifier, Retry-After, idempotency, body replay, budget, breaker) are built and tested first in isolation; then `Transport.RoundTrip` composes them around a single attempt loop in `attempt.go` that handles both retries and hedges over one results channel.

**Tech Stack:** Go 1.25+ standard library only. Tests use `testing`, `testing/synctest` (fake time, built-in goroutine-leak detection), and `net/http/httptest`.

**Spec:** `docs/superpowers/specs/2026-10-21-gotry-design.md` — read it alongside this plan; section numbers (§) below refer to it.

## Global Constraints

- Module path `github.com/MrVSiK/gotry`; package name `gotry`; all source files at the repo root.
- `go.mod` declares `go 1.25`. No `require` lines — standard library only, tests included.
- Never mutate the caller's `*http.Request`; every attempt uses `req.Clone(attemptCtx)`.
- Always close `req.Body` (the RoundTripper contract), and drain+close every response body that is not returned to the caller.
- `Transport` must be safe for concurrent use; every test runs with `-race`.
- Defaults: MaxAttempts 3; backoff `ExponentialJitter(100ms, 5s)`; retryable statuses {502, 503, 504} plus 429; MaxRetryAfter 30s; idempotency headers `Idempotency-Key`, `X-Idempotency-Key`; MaxBufferedBody 1 MiB (1<<20); budget (ratio 0.2, minPerSec 10); breaker off; hedging off; discarded-body drain limit 64 KiB.
- Breaker defaults when enabled with zero fields: FailureThreshold 5, OpenDuration 10s, HalfOpenProbes 1.
- Error strings are prefixed `gotry: `.
- Every commit message ends with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Git identity is already configured for this repository; commit on branch `gotry-design`.

## Review Focus

1. **Caller reads the winning body slower than the per-attempt timeout.** It must not be truncated: the per-attempt timeout covers only the time until response headers arrive. Test: Task 8, `TestPerAttemptTimeoutDoesNotTruncateBody`.
2. **A request body with no `GetBody`,** for example `io.NopCloser(strings.NewReader(...))` set by hand. The server must receive identical bytes on every attempt. Test: Task 8, `TestRetryReplaysBodyWithoutGetBody`.
3. **Caller context cancelled during the backoff sleep.** Return promptly with the context error, make no further attempts, and leave no goroutines behind. Test: Task 8, `TestCancelDuringBackoffReturnsPromptly`.
4. **`http.Client.Timeout` or another context deadline shorter than `Retry-After`.** Return the 503 immediately rather than sleeping past the deadline. Test: Task 8, `TestRetryAfterBeyondDeadlineReturnsResponse`.
5. **A 503 held while a hedge is still in flight, and that hedge then fails with a connection error.** The caller gets the 503 with a readable body, not an error. Test: Task 9, `TestHedgePrefersResponseOverLaterError`.

        if got < base || got > max { t.Fatalf("iter %d: %v outside [%v,%v]", i, got, base, max) }
        prev = got
    }
}

- [ ] **Step 4: Implement `backoff.go`**

- **Exponential:** `base << (retry-1)`. Stop shifting and return `max` once the value would reach or pass `max`, or once `retry-1 >= 62`.
- **Full jitter:** `rand.N(exp)` from `math/rand/v2`, where `exp` is the capped exponential value. `rand.N` returns a value in [0, exp); return 0 when exp is 0.
- **Decorrelated jitter:** treat `prev < base` as `base`. Set `hi = min(max, prev*3)` and return `base + rand.N(hi-base+1)`, capped at `max`.

### Task 4: Body replay, body lifetime and draining

**Files:**
- Create: `body.go`
- Test: `body_test.go`

**Interfaces:**
- Produces (unexported):
  - `type bodySource struct { replayable bool; get func() (io.ReadCloser, error) }`
  - `func newBodySource(req *http.Request, maxBuffer int64) (bodySource, error)`. The rules come from §7.3:
    - A nil body or `http.NoBody` is replayable, and `get` returns `http.NoBody`.
    - A non-nil `GetBody` is replayable, and `get` is `req.GetBody`.
    - Otherwise read up to `maxBuffer+1` bytes. If they fit, close the original body; the source is replayable and `get` returns a fresh `io.NopCloser(bytes.NewReader(buf))` each time.
    - If the body is larger, the source is *not* replayable. `get` returns a reader built from `io.MultiReader(bytes.NewReader(prefix), original)`, and its `Close` closes the original.
    - On a read error, close the original and return the error.
  - `func wrapBody(rc io.ReadCloser, release func()) io.ReadCloser`. `release` runs exactly once, at the first of `Close()` or a read returning `io.EOF`. Use `sync.Once`.
  - `func drainAndClose(rc io.ReadCloser)`. Copy at most 64<<10 bytes to `io.Discard`, then close. A nil `rc` is a no-op.

- `TestBodySourceNil`: for `req.Body == nil`, `replayable` is true and `get` returns `http.NoBody`.
- `TestBodySourceGetBody`: the request comes from `http.NewRequest("POST", u, strings.NewReader("abc"))`, which sets `GetBody`. Three calls to `get` each read `"abc"`.
- `TestBodySourceBuffersSmallBody`: the body is `io.NopCloser(strings.NewReader("hello"))` wrapped in a `closeTracker`, and `GetBody` is nil. The source is replayable, three calls to `get` each read `"hello"`, and the tracker reports the original was closed.

### Task 6: Circuit breaker

**Files:**
- Create: `breaker.go`
- Test: `breaker_test.go`

**Interfaces:**
- Produces:
  - `type BreakerState int`, with `Closed BreakerState = iota`, `Open` and `HalfOpen`. `String()` returns `"closed"`, `"open"` or `"half-open"`.
  - `type BreakerConfig struct { FailureThreshold int; OpenDuration time.Duration; HalfOpenProbes int }`
  - `var ErrCircuitOpen = errors.New("gotry: circuit open")`
  - Unexported: `type outcome int`, with `outcomeSuccess`, `outcomeFailure` and `outcomeIgnore`.
  - Unexported: `type breakers struct { ... }`, a per-host registry kept in a `sync.Map` of mutex-guarded host states.
  - `func newBreakers(cfg BreakerConfig, onChange func(host string, from, to BreakerState)) *breakers`. Zero fields take the defaults 5, 10s and 1. `onChange` may be nil, and it is called *after* the host mutex is released.
  - `func (b *breakers) admit(host string) (probe, ok bool)`. On a nil receiver it returns `(false, true)`.
    - **Closed:** `(false, true)`.
    - **Open:** once `OpenDuration` has elapsed, move to HalfOpen and fall through. Before then, `(false, false)`.
    - **HalfOpen:** if a probe slot is free, take it and return `(true, true)`. Otherwise `(false, false)`.
  - `func (b *breakers) allow(host string) bool`. Used for second and later attempts. True only when the state is Closed; it never takes a probe slot. On a nil receiver it returns true.
  - `func (b *breakers) report(host string, probe bool, o outcome)`. Does nothing on a nil receiver.
    - **Probe report:** release the slot first. A success moves the host to Closed and resets its counter. A failure moves it to Open with a fresh timestamp. An ignore leaves the state alone.
    - **Non-probe report in Closed:** a success resets the consecutive-failure count. A failure increments it, and reaching the threshold moves the host to Open.
    - **Non-probe report in Open or HalfOpen:** ignored.

- `TestBreakerSuccessResetsCount`: report fail, fail, success, fail, fail. The breaker is still Closed.
- `TestBreakerPerHost`: 5 failures on `"a"` and none on `"b"`. Host `"a"` is denied and `"b"` is admitted.
- `TestBreakerHalfOpenProbe`: use `OpenDuration: 10s` and open the breaker. After `time.Sleep(10*time.Second)`, `admit` returns `(true, true)`, a second `admit` returns `(false, false)`, and `allow` is false. A probe success leaves the state Closed. - `TestBreakerNil`: on a nil `*breakers`, `admit` returns `(false, true)`, `allow` returns true, and `report` doesn't panic.

**Interfaces:**

  - `func NewTransport(base http.RoundTripper, opts ...Option) *Transport`. A nil `base` becomes `http.DefaultTransport`. It builds `budget` with `newBudget`. When `cfg.breaker != nil` it builds `breakers` with `newBreakers(*cfg.breaker, cfg.hooks.breakerChange)`.

  - `func (t *Transport) CloseIdleConnections()`. Forwards to `base` when it implements `interface{ CloseIdleConnections() }`.
  - Unexported in `attempt.go`: `func (t *Transport) run(req *http.Request, p effectivePolicy, src bodySource, probe bool) (*http.Response, error)`. Task 9 extends it with hedging.

**What `RoundTrip` does (§7.1):**
1. Compute `p := t.cfg.policy`; if `policyFrom(req.Context())` returns a policy, use `p = p.merge(...)`.
2. Call `probe, ok := t.breakers.admit(req.URL.Host)`. If `!ok`, close `req.Body` when it is non-nil and return `nil, ErrCircuitOpen`.
3. Call `t.budget.deposit()`.
4. Call `src, err := newBodySource(req, t.cfg.maxBufferedBody)`. On an error, report `outcomeIgnore` to the breaker if `probe` is set, then return the error.
5. A request is eligible when:
   `(isIdempotentMethod(req.Method) || hasIdempotencyKey(req.Header, t.cfg.idemHeaders) || p.allowNonIdempotent) && src.replayable`.
   If it isn't eligible, or if `probe` is set, use `p.maxAttempts = 1` and `p.maxHedges = 0`.
6. `return t.run(req, p, src, probe)`.

**What `run` does (§7.2 and §7.4).** Here, "launch attempt n" means:

1. Create `actx, cancel := context.WithCancelCause(req.Context())`.
2. If `p.perAttemptTimeout > 0`, set `timer := time.AfterFunc(p.perAttemptTimeout, func(){ cancel(errAttemptTimeout) })`, where `var errAttemptTimeout = attemptTimeoutError{}`.
3. Build the clone with `r := req.Clone(actx)`, setting `r.Body` from `src.get()` and `r.GetBody` to `src.get` when `src.replayable`.
4. Run `go func(){ resp, err := t.base.RoundTrip(r); timer.Stop(); if context.Cause(actx) == errAttemptTimeout && err != nil { err = errAttemptTimeout }; results <- result{n, resp, err} }()`.
5. Keep `cancel` in an `inflight map[int]context.CancelCauseFunc`.

`results` is buffered with `p.maxAttempts + p.maxHedges` slots, so attempt goroutines never block.

When result `res` arrives:
- If `req.Context().Err() != nil`:
  - Cancel everything that is still running.
  - Drain and close `res.resp` and any retained response.
  - Start the background drainer for the attempts still in flight.
  - Report `outcomeIgnore` if `probe` is set.
  - Return `nil, req.Context().Err()`.
- Otherwise compute `retry := decide(Attempt{r, resp, err, n}, p.classifier, t.cfg.retryableStatuses)`. Report `outcomeFailure` to the breaker when `retry` is true and `outcomeSuccess` when it is false, passing the `probe` flag.
- **When `retry` is false, `res` wins.**
  - Cancel the other in-flight attempts with `context.Canceled`.
  - Drain any retained response.
  - Start a background drainer that receives the remaining in-flight results, drains and closes their bodies, and calls their cancels.
  - If `res.resp != nil`, set `res.resp.Body = wrapBody(res.resp.Body, func(){ cancel(nil) })` using this attempt's own cancel, and return it.
  - Otherwise call `cancel(nil)` and return the error. Wrap it in `*Error` when more than one attempt was launched.
- **When `retry` is true, keep the result.**
  - A response replaces the retained response. Drain the older one and call its cancel.
  - An error sets `lastErr`, then the attempt's cancel is called.
  - Then decide whether to continue: stop if `launched == p.maxAttempts`, if `!t.breakers.allow(host)`, or if `!t.budget.withdraw()`. On stopping, give up as described below.
  - Otherwise work out the delay. If the retained response is a 429 or 503 and its `Retry-After` header parses:
    - if the value is greater than `t.cfg.maxRetryAfter`, give up;
    - otherwise the delay is that value.
  - Without a usable `Retry-After`, the delay is `p.backoff.Delay(retryNum, prevDelay)`.
  - If the caller's context has a deadline and `time.Now().Add(delay)` is after it, give up.
  - Otherwise fire `OnRetry` with the attempt number, delay, status code, error and whether `Retry-After` was used. Then sleep using `select` on a `time.NewTimer(delay)` and `req.Context().Done()`. If the context finishes first, follow the cancellation path above. Then launch the next attempt.
- **Giving up:**
  - If a response is retained, wrap its body with its cancel and return it with a nil error.
  - Otherwise return `lastErr` wrapped as `&Error{Attempts: launched, Err: lastErr}`, or unwrapped when only one attempt was launched.

`helpers_test.go` defines the fake `RoundTripper`:

```go
type step struct {
    status int
    header http.Header
    body   string
    err    error
    delay  time.Duration // waits (respecting r.Context()) before answering
}
type scriptRT struct {
    mu     sync.Mutex
    steps  []step   // step i answers call i; calls past the end repeat the last step
    calls  int
    bodies []string // request bodies received, in call order
    resps  []*closeTracker // every response body handed out
}
func (s *scriptRT) RoundTrip(r *http.Request) (*http.Response, error)
func (s *scriptRT) allClosed() bool
```

If the context finishes during `delay`, `RoundTrip` returns `context.Cause(r.Context())` when it is set, and `r.Context().Err()` otherwise. Every response body is a `closeTracker` that wraps `strings.NewReader(body)`.
